# SG-CONTENT requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and evidence for each ID are computed, never written here; this file defines what each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `SG-CONTENT-R001` | **`skill_graphs` is served as a content-only connector (rollup).** The package declares exactly one entry point, `scion_sdk.connector = "skill_graphs"`, and no provider entry-point group. Every graph under `skill_graphs/skills/` is then a native MCP skill resource. Children `.1` to `.4` deliver it. | See each child. |
| `SG-CONTENT-R001.1` | **One content-only declaration.** Caller chain: `scion_sdk.connector.resolve_connector("skill_graphs")` reads the entry-point table of the installed distribution (`SCION-CONNECTOR-CONTROL-R071.1`). Shape: `pyproject.toml` declares `[project.entry-points."scion_sdk.connector"]` with the single value `skill_graphs` (a bare package, so content only), depends on `scion-sdk[mcp]>=0.6.5,<0.7.0`, and declares no other entry-point group. | `tests/test_catalog_content.py::test_declares_one_content_only_entry_point` reads `pyproject.toml` and finds one entry point, the bare package, the SDK floor and cap, and no other group. |
| `SG-CONTENT-R001.2` | **Content sits where the convention expects it.** Caller chain: `scion_sdk.connector.content_dirs` maps the package to its `skills/` directory. Shape: every graph lives at `skill_graphs/skills/<name>/SKILL.md`, one level deep. The frontmatter `name` equals the folder name. Supporting files stay inside the graph folder. | `tests/test_catalog_content.py::test_every_skill_is_flat_and_named_by_folder` finds no name that differs from its folder. |
| `SG-CONTENT-R001.3` | **Every graph is served natively.** Caller chain: `scion_sdk.connector.build_server("skill_graphs")` registers fastmcp's `SkillsDirectoryProvider`. Shape: the server lists one `skill://<name>/SKILL.md` resource for every graph folder under `skills/`. | `tests/test_catalog_content.py::test_server_lists_every_skill` builds the server in process and compares the listed names with the folders. |
| `SG-CONTENT-R001.4` | **No graph lives outside `skills/`.** Caller chain: the SDK content convention reads only `skill_graphs/skills/`. Shape: `skill_graphs/laravel-docs`, `skill_graphs/quant-career-docs`, `skill_graphs/trading-systems` and `skill_graphs/infrastructure-blueprints` move to `skill_graphs/skills/<name>`, and no `SKILL.md` remains outside it. Refusal: the test names each stray folder. Depends: `SG-CONTENT-R001.2`. | `tests/test_catalog_content.py::test_no_skill_graph_outside_skills_folder` (planned, see test-spec). |
| `SG-CONTENT-R002` | **Every graph is a validated distillation (rollup).** A graph distills one body of knowledge into a `SKILL.md` index over a flat `reference/` corpus, with an `index.json` map and a `sources.json` provenance record. The `skill-graph-builder` skill writes it (`US-SKILL-GRAPH-BUILDER-R001`). Gate `validate-skill-graphs` checks it. Children `.1` to `.7` deliver it. | See each child. |
| `SG-CONTENT-R002.1` | **Managed graph contract.** Caller chain: pre-commit hook `validate-skill-graphs` runs `scripts/validate_skill_graphs.py::main`. Shape: a graph with `sources.json` has a `SKILL.md` whose `name` equals its folder and whose `description` is non-empty. `sources.json` has schema `skill-graph-sources/v1`, and every source `kind` is in the closed set `SOURCE_KINDS`. | `tests/test_validate_skill_graphs.py::test_gate_passes_for_valid_managed_graph` (bound). |
| `SG-CONTENT-R002.2` | **Flat reference corpus.** Caller chain: as `R002.1`, through `validate_flat_reference`. Shape: every file under `reference/` sits exactly one level deep, named by a short hash of its source. Refusal: a nested file fails the gate and names the path. | `tests/test_validate_skill_graphs.py::test_gate_fails_on_nested_reference_file` (bound). |
| `SG-CONTENT-R002.3` | **Declared size matches the corpus.** Caller chain: as `R002.1`, through `validate_managed`. Shape: the frontmatter `file_count` equals the number of `reference/*.md` files. Refusal: a mismatch fails the gate and names the graph. | `tests/test_validate_skill_graphs.py::test_gate_fails_on_file_count_mismatch` (bound). |
| `SG-CONTENT-R002.4` | **Index and manifest resolve with matching digests.** Caller chain: as `R002.1`, through `validate_index_paths` and `validate_sources_paths_and_sha`. Shape: every `index.json` section path and every `sources.json` file path exists. Every recorded `sha256` equals the file digest. Refusal: a missing path or a digest mismatch fails the gate. | `tests/test_validate_skill_graphs.py::test_gate_fails_on_sources_sha256_mismatch` (bound). |
| `SG-CONTENT-R002.5` | **The wheel carries the whole corpus portably.** Caller chain: `python -m build` packs `skill_graphs/**` through `[tool.setuptools.package-data]`. Shape: every indexed resource and hidden file is in the wheel and the sdist, and no path breaks the length limits of the constitution. | `tests/test_wheel_portability.py::test_wheel_contains_indexed_resources` (bound, marked slow). |
| `SG-CONTENT-R002.6` | **Every graph carries a manifest.** Caller chain: as `R002.1`. Shape: `main` fails a graph that has `reference/` and no `sources.json`; the legacy count and the "reported, never failed" branch are deleted. `django-docs`, `neo4j-docs`, `tanstack-docs` and the four `trading-*` graphs are rebuilt by the builder. Depends: `US-SKILL-GRAPH-BUILDER-R002`. | `tests/test_validate_skill_graphs.py::test_gate_fails_on_graph_without_manifest` (planned, see test-spec). |
| `SG-CONTENT-R002.7` | **A graph names its builder and its type.** Caller chain: as `R002.1`. Shape: `sources.json` holds non-empty `builder_version` and `built_at`. `SKILL.md` frontmatter declares `skill_type: graph`, the key the engine reads (`MEDULLA-TYPED-PACKS-R700.7`). Refusal: a missing field fails the gate and names it. | `tests/test_validate_skill_graphs.py::test_gate_fails_on_missing_builder_fields_or_graph_type` (planned, see test-spec). |
| `SG-CONTENT-R003` | **Each graph's concept layer is an ontology module (rollup).** A graph may carry an ontology that layers its concepts on the knowledge graph. The module is `skill_graphs/ontology/<graph>.ttl`, which the SDK convention serves as an ontology entry of the pack. The engine imports it (`MEDULLA-TYPED-PACKS-R701`). Children `.1` to `.4` deliver it. | See each child. |
| `SG-CONTENT-R003.1` | **Module layout.** Caller chain: `scion_sdk.connector.content_dirs` exposes `ontology/`. Shape: one Turtle file `skill_graphs/ontology/<graph>.ttl` per graph with a concept layer. Its ontology IRI is `http://knuckles.team/kg/skillgraph/<graph>`. Depends: `SG-CONTENT-R001.1`. | `tests/test_skill_graph_ontology.py::test_module_is_named_by_graph_and_parses` (planned, see test-spec). |
| `SG-CONTENT-R003.2` | **Every class rolls up to the engine core.** Caller chain: gate `validate-skill-graphs` calls `validate_ontology_modules` (new, `scripts/validate_skill_graphs.py`). Shape: each declared class has an `rdfs:subClassOf` path to a class of `http://knuckles.team/kg`. The module has no `owl:imports` of the core. Refusal: the gate names each orphan class and each core import. Depends: `SG-CONTENT-R003.1`, `MEDULLA-TYPED-PACKS-R105`. | `tests/test_skill_graph_ontology.py::test_orphan_class_and_core_import_fail_the_gate` (planned, see test-spec). |
| `SG-CONTENT-R003.3` | **The manifest names the layer.** Caller chain: as `R002.1`. Shape: `sources.json` `kg_ontology` is the module file stem or `null`, and `concepts` lists the module class IRIs. The five graphs (`redis-docs`, `minio-docs`, `framer-docs`, `pytorch-docs`, `reactrouter-docs`) that name the retired package in `kg_ontology` are rebuilt. Depends: `SG-CONTENT-R003.1`, `US-SKILL-GRAPH-BUILDER-R003`. | `tests/test_skill_graph_ontology.py::test_manifest_layer_matches_module` (planned, see test-spec). |
| `SG-CONTENT-R003.4` | **Hot-path proof.** Caller chain: `scion_sdk.artifacts.pack.build_connector_content_pack` builds the pack from the installed package. Shape: the test finds one skill entry and one ontology entry per layered graph in the archive. The served import proof is `MEDULLA-TYPED-PACKS-R701.5`. Depends: `SG-CONTENT-R003.1`. | `tests/test_skill_graph_ontology.py::test_pack_holds_one_skill_and_one_ontology_per_layered_graph` (planned, see test-spec). |
